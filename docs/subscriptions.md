# 订阅与推送

订阅让机器人定期检查贴吧的新内容，并发送到指定群聊或私聊。它有两种类型：

| 类型 | 目标 | 推送内容 |
| --- | --- | --- |
| 关注用户 | 贴吧数字 UID，或该用户的帖子链接 | 该用户新发布、且接口可见的主题帖 |
| 追踪楼主 | 帖子链接或数字帖号 | 该帖子楼主新发布的普通楼层 |

关注用户不推送该用户在别人的帖子中的回帖；追踪楼主不推送其他人的回复、楼中楼或已有楼层的编辑。

## 创建一个订阅

先在插件配置中开启「订阅与更新推送 → 启用订阅推送」。全局开关默认关闭；订阅仍可保存和管理，但关闭时不会检查或发送。

在希望接收推送的聊天中发送：

```text
爱丽丝贴吧 关注 <该用户的帖子链接或数字UID>
爱丽丝贴吧 追踪 <帖子链接或帖号>
```

机器人返回的订阅 ID 用于暂停、恢复、检查和删除。使用 `爱丽丝贴吧 订阅` 可以找回当前会话的 ID。指令前缀由 AstrBot 配置决定。

也可在 WebUI 的「订阅」页创建。推送会话标识必须完整填写：在目标聊天发送 `爱丽丝贴吧 会话`，复制返回值。直接填写群号、QQ 号或平台名称不能代替这个标识。

不知道 UID 时，填写目标用户发布的一个可访问帖子链接即可。插件会读取该帖楼主的数字 UID，保存为用户订阅；关注对象始终是该帖楼主。数字 UID 是贴吧账号的固定数字标识，当前版本不通过昵称、QQ 号或头像 portrait 字符串查找用户。

## 第一次检查与后续检查

**首次成功检查用于建立基线，记录当前更新位置。** 它不会将用户历史帖子或帖子已有楼层全部推送出来。运行活动显示基线成功后，后续检查才会推送新增内容。

基线完成后，检查发现新内容才加入发送队列。推送以简短正文、主题/楼层信息和可点击的原帖链接为主；不会自动下载该更新里的全部图片与视频。需要完整解析时，将原帖链接与解析关键词发给机器人即可。

默认每 300 秒检查，最小允许 60 秒。每轮按预算处理订阅，接口请求也会节流，因此这一间隔不是送达时间保证。

## 筛选、备注与管理

WebUI 可为订阅设置备注、关键词和推送会话。备注用于识别订阅，不影响原帖内容。关键词每行一个，留空接收所有更新；填写后，只推送标题或摘要中包含任一关键词的更新，匹配不区分大小写。筛选后跳过的内容不会因后续修改关键词而自动补发。

| 操作 | 效果 |
| --- | --- |
| 暂停 | 保存订阅和检查位置，停止该订阅的检查与发送 |
| 恢复 | 从保存的状态继续检查，补查暂停期间仍可见的新内容 |
| 手动检查 | 在推送开关和订阅状态允许时，执行一次检查 |
| 删除 | 取消该订阅，移除其追踪状态 |

聊天命令默认仅管理员可用，且只能操作当前会话的订阅。WebUI 依赖 AstrBot 登录权限，可以管理全部会话。更改聊天权限设置前，请考虑群成员是否应该自行创建推送。

## 持久化与失败处理

订阅、基线、检查位置及待发送内容保存在本插件的数据存储中。正常重启或热重载会保留这些状态；卸载、删除插件数据或重新创建订阅会影响追踪连续性。

每条内容使用帖子或楼层的标识去重。发送成功后才确认已处理；发送失败时保留待发送内容，并在后续检查重试。若平台已收到消息但未返回成功结果，重试仍可能造成重复消息。

每个订阅每轮默认最多扫描 20 页、推送 10 条，未处理完的内容继续按预算处理。访问失败时保留状态，运行活动会显示错误或等待重试；无需为了重试删除并重新订阅，重新创建会重新建立基线。

单个用户订阅最多保存 10000 条内容的去重记录。达到上限后会明确报错并保留数据；需要取消后重新订阅建立新基线。新基线以前的内容不会补发。

## 为什么没有收到消息

按以下顺序检查：

1. 全局「启用订阅推送」是否开启，该订阅是否处于启用状态。
2. 首次基线是否已完成，目标是否在基线建立后发布了新内容。
3. 推送会话是否由目标聊天返回，平台适配器是否在线。
4. 关键词是否过滤了该内容。
5. 运行活动是否显示网络、平台访问限制或发送失败。

隐藏动态、删帖、平台风控及接口变化都可能让内容不可见。关注用户获取的是接口公开可见的主题，不等同于用户完整发帖档案。推送不能保证获取到平台未提供的更新。
